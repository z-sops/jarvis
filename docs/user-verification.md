### Native containment and outage recovery (2026-10-10)
Native crew execution now requires an explicitly selected, already installed immutable Docker Linux image ID. Orbit does not pull images or fall back to host execution. The image must contain Node 20+ and the selected native CLI; actual native CLI compatibility remains unverified. Run `npm run test:containment -- <installed-sha256-image-id>` on the Windows machine to check the real boundary without a provider call. An open Docker Desktop window alone is not evidence that these checks pass.

Native file snapshots are taken before model requests and, when files change, every ten seconds. The host validates paths and hashes, flushes files and snapshot metadata, then atomically updates the owning job's checkpoint pointer. Job retry carries that pointer and restores the last valid snapshot into the same private workspace. Network failure does not replay a request. Restart cleanup must confirm the old owned container is stopped before the worker can execute again. Historical approval receipts do not grant fresh approval; unknown request reservations and ambiguous tool outcomes remain protected by the existing broker's inspection rules.

Recovery can retrieve saved local files and history while offline; it cannot retrieve an unreceived remote response or continue a cloud model without connectivity. Work since the last completed checkpoint may be lost. Conflicting user edits, corrupted snapshots and unknown cleanup require inspection. Snapshot capture and applying several project files are not one atomic filesystem transaction. Windows directory-flush semantics and physical power-cut recovery still require verification on the user's machine. Tests with a restarted Home instance prove persisted metadata/file retrieval, not physical power-loss guarantees.

Settings **Check runtime** performs the same contained isolation check plus the selected CLI version without a model call. Office displays stopped/unknown container state and last saved checkpoint time. For MCP/browser, verify the selected real CLI reaches the existing Orbit gateway through the scoped relay; confirm owning actor, fresh permission behavior, managed policy and cancellation. Host actor/provider/connector credentials must not appear in the container. Direct networking and dependency downloads stay blocked; provision approved CLI/provider packages inside the image ahead of time. Inline OpenCode runtime configuration overrides project model/permission settings; actual supported-version behaviour still needs a real task check.
